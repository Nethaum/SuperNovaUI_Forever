# Architecture

`Core/` (except `Config.lua`) and `Panel/` are copied from the Retail repository by its `tools/sync-shared.py`: do not edit them here.
Run the tests from the Retail repository: `python tests/run_tests.py <this addon folder>`.

Same shape as the Retail addon, kept small:

- The addon namespace table (`local addonName, SN = ...`) is the public project table.
- Modules register with `SN:RegisterModule(name, module)` and `SN:RegisterModuleDefaults(name, defaults)`.
- The bootstrap initializes the database, registers `/snui`, then initializes modules in registration order.
- Account options live in `SuperNovaUIForeverDB`, character options in `SuperNovaUIForeverCharDB` (different from the Retail
  addon's variables on purpose).
- One module owns one feature; add each new file to both `.toc` files.
- `Modules/CooldownMacro.lua` and `Modules/Exploration.lua` are copied from the Retail repository too (see its `docs/ARCHITECTURE.md`, which also explains how modules that are useless or conflict start off): do not edit them here.
- `Data/Exploration.lua` is generated for this client (1.60.1) by the Retail repository's `tools/gen-exploration.py`.
- `Modules/Forever/Goal*.lua` (Profession goal) exists only here, split by job (`GoalStore` saved data keyed by profession id, never by translated name; `GoalGame` reads the game; `GoalRecipes` recipe levels; `GoalPage` settings page; `GoalReport` summary and texts; `Goals` the box, events, command and registration); the paragraph below describes the whole module. It holds no profession, recipe or item data: the goal is a number and a label the player types, per profession name; names and recipe colours come from the game (`GetTradeSkillLine`, `GetTradeSkillInfo`), so they are in the client's language. The level of a recipe comes from a list of the Forever recipes, `{ spellId, "English name", min = skill needed }` per profession, matched by the spell's name in the client's language: the copy inside the addon, `Data/Recipes.lua` (`SN.RecipeData`); VoidProf is not read at run time, which `tools/gen-recipes.py` makes from VoidProf's data file. VoidProf is MIT licensed, so its notice is in `SuperNovaUI_Forever/THIRD_PARTY_NOTICES.md` (it goes into the zip). When no list knows a name, the recipe item's tooltip (`ITEM_MIN_SKILL`) in the vendor window or the bags is tried, and a recipe the character already knows is accepted; any other name is refused. To refresh the list after a game patch: update VoidProf, run the script, run the tests. `Modules/Forever/GoalPlan.lua` is the cheapest-path maths (pure, no window): per craft the recipe with the lowest price per expected skill point (orange gives `ups`, yellow to grey falls off linearly), recipe books paid once and spread over the points they can still give. Prices, lowest wins: Auctionator (`Auctionator.API.v1.GetAuctionPriceByItemID`) or TradeSkillMaster (`TSM_API.GetCustomPriceValue`, not tested against the real addon), and vendor prices the module saw at a merchant window (unlimited gold stock of items in the recipe data, kept in `vendorSeen`) or VoidGPS (`VoidGPS.Goods:Get(item)` -> `{ buy = copper for qty, qty, vendors = { { limited, cost, rep ... } } }`, checked against VoidGPS 0.8.9; it is GPL-3.0, so it is only called, never copied; its data lists which vendors sell an item, e.g. Hot Spices yes, the clam meats no). The recipe data deliberately has no buy price: it says nothing about who sells an item, so an item without those prices is unknown, not estimated, and a recipe with an unknown price is used only when no priced one can give points (the plan is then marked incomplete). Not counted: owned items, training, selling the crafts. It starts off until a goal is set.
- `Modules/Forever/Convergence.lua` (Elemental Convergence markers) exists only here. Its positions, `Data/Convergence.lua`, were copied from the Wowhead page of the object (616992) because the client tables do not hold them; it starts on only for a Windshaper Skyborne (race 96, or anyone who knows Skysight). When the addon Skyborne Leyline & Convergence Marker (folder `SkyborneLeyLineConvergenceMarker`, an optional dependency in the toc) is installed, the module reads its list through the public `SLLCM_GetNodes("Horde")` (kept until the next refresh) and falls back to our own for zones it lacks; it also declares it in `conflictsWith`, so it starts off next to it.
